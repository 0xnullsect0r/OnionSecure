# 🧅 OnionSecure

> HTTPS-upgrading browser-in-browser proxy for the Tor network.

Many `.onion` hidden services serve content over plain HTTP. While Tor provides transport-layer encryption, browsers still show "Not Secure" and there is no TLS certificate. **OnionSecure** solves this by acting as a self-hosted HTTPS proxy that fetches `.onion` content server-side through Tor and serves it to you over HTTPS — all within a single Docker Compose stack.

```
You (Tor Browser)
    │  HTTPS (.onion address)
    ▼
Caddy  ──  self-signed TLS termination
    │  HTTP :3000
    ▼
Next.js Proxy App  ──  rewrites all URLs, injects toolbar
    │  SOCKS5 :9050
    ▼
Tor Daemon  ──  hidden service + outbound SOCKS proxy
    │  Tor network
    ▼
Target .onion site (HTTP or HTTPS)
```

## Features

- **HTTPS upgrade** — your browser always sees a padlock; HTTP-only `.onion` sites are fetched server-side
- **Browser-in-browser** — persistent toolbar (URL bar, reload) injected into every page
- **Full URL rewriting** — `href`, `src`, `action`, `srcset`, CSS `url()`, `@import`, meta-refresh
- **Zero logs** — no Docker logs, no Tor logs, no Next.js request logs, nothing written to disk
- **Persistent onion address** — Ed25519 key stored in a named Docker volume; address never changes
- **No host ports exposed** — the service is only reachable through Tor

## Prerequisites

- [Docker](https://docs.docker.com/get-docker/) and [Docker Compose](https://docs.docker.com/compose/) (v2+)
- [Tor Browser](https://www.torproject.org/download/) to access the service

## Quick Start

```bash
git clone https://github.com/0xnullsect0r/OnionSecure.git
cd OnionSecure
./start.sh
```

`start.sh` builds and starts all containers, then prints your onion address:

```
✅ OnionSecure is live!

  https://xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.onion
```

Open that address in **Tor Browser**. Accept the self-signed certificate warning (click *Advanced → Accept the Risk*). You'll be greeted with the OnionSecure home page.

## Get the Address Later

```bash
./get-onion.sh
```

## Usage

1. Open the onion address in Tor Browser
2. Enter any `.onion` URL in the address bar
3. OnionSecure fetches the page through Tor and serves it to you over HTTPS
4. Use the toolbar at the top of every page to navigate

## Architecture

| Service | Image | Role |
|---|---|---|
| `tor` | debian:bookworm-slim + tor | Tor daemon: hidden service + SOCKS5 proxy on :9050 |
| `app` | node:20-alpine | Next.js proxy app on :3000 |
| `caddy` | caddy:2-alpine | HTTPS reverse proxy on :443 (`tls internal`) |

### No-Log Policy

| Layer | Mechanism |
|---|---|
| Docker | `logging: driver: "none"` on all services |
| Tor | `Log notice /dev/null` + `SafeLogging all` + `AvoidDiskWrites 1` |
| Caddy | `log { output discard }` |
| Next.js | `NEXT_TELEMETRY_DISABLED=1`, no request logging |

### Persistent Keys

The Tor hidden service Ed25519 private key is stored in the `tor-keys` Docker named volume. As long as this volume exists, your onion address will remain the same across restarts.

> ⚠️ **Backup this volume** if you want to preserve your onion address. Deleting it generates a new address permanently.

## Stopping

```bash
docker compose down
```

To also remove the onion key volume (generates a new address next time):

```bash
docker compose down -v
```

## Security Notes

- The self-signed certificate is generated by Caddy on first start. Tor hidden services already provide end-to-end encryption; HTTPS adds a second layer and eliminates browser "Not Secure" warnings.
- JavaScript from proxied pages is passed through unmodified. Complex web apps may not work perfectly.
- Cookies from target sites are not forwarded — the proxy is stateless with respect to target sessions.
- `Referer` and other identifying headers are never forwarded to target sites.
- All DNS resolution happens through Tor (SOCKS5h mode).
